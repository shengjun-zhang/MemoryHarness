# 步预算耗尽是第二大失败原因——如何合理分配节奏

**Observed:** 2026-07-28 single-agent AI2-THOR benchmark 中，33.1%
（103/311）的失败是 `Reached maximum step limit`（12/14/16/18/20 步
不等，取决于任务的 golden_actions 步数）。平均 `golden_actions` 只有
9.31 步，而平均 `actual_actions` 达到 9.62 步——很多任务的实际执行步数
明显超过最优解，其中相当一部分是把预算浪费在了导航绕障（见
`feedback_navigation_blocking.md`）和交互重试（见
`feedback_object_interaction_gotchas.md`）上，而不是任务本身需要的
操作步骤。

## 观测到的主要浪费来源

1. **无效的探索循环**——没有清晰的搜索策略地反复旋转/移动，重复扫描
   已经看过的区域。
2. **恢复性内耗**——对一个被阻挡/失败的动作只做微小变化反复重试，而
   不是在 1-2 次失败后果断切换策略（见 `feedback_navigation_blocking.md`
   与 `feedback_not_in_view_distance_rule.md`，这是这个失败类别里两个
   最大的贡献来源）。
3. **动作失败后未察觉、继续原地重复**——见
   `feedback_action_failure_blindness.md`：有些案例甚至没有真正触顶
   step limit 就已经因为幻觉式完成而失败，但也有些案例是反复重试
   同一个报错动作，最终耗尽预算。

## 节奏把控建议

- **预算意识**：从任务一开始的系统提示词/上下文里就知道自己的
  `max_steps`。经验法则：一旦消耗过半预算（约 50%-60%）却仍处于纯
  探索阶段、还没有定位到任务相关物体，应当把这视为紧急情况——优先做
  系统性的区域覆盖（选一个尚未探索的方向，不要重复扫描已经确认过没有
  目标的区域），而不是继续投机式漫游。
- **在恢复循环上快速止损**：如果同一类错误（"not in view"、
  阻挡、交互失败）针对同一个目标已经连续发生 2 次以上，立即切换到
  完全不同类别的策略（比如从"直接靠近"切换为"先绕到侧面再靠近"），
  而不是对同一个修复方法做第三次小幅变体尝试。
- **在了解大致方向后优先选择果断的大步移动**（开阔区域使用
  `MoveAhead(Large)`/默认步长），把 `Small` 步幅留给靠近目标时的精细
  定位，或反复超调的场合。
- **主动构建空间记忆**：虽然没有搭档可以沟通"已经搜索过的区域"，也应
  该在自己的 `<THINK>` 里显式记录"我已经检查过厨房，没有发现目标"，
  避免依赖脆弱的隐式记忆重复走回头路。
- **不要用无意义的动作填充步数**：每一步都应该带来新的信息或朝目标
  推进，不要为了"稳妥"而做重复性的确认动作。
