# AI2-THOR 统一动作空间中的物体交互坑点

这些问题在总量上小于头部几类问题（"not in view"、导航阻挡、DONE 被拒、
幻觉式完成），但每一个都是一旦识别就能确定性解决的坑点。

## 交互距离是严格的，且以物体表面为准

最大交互距离是 **1.0 米**，从你到物体**表面**（而不是中心点）测量。
一个在广角画面里"看起来很近"的物体仍然可能刚好超出 1.0m——如果交互
因为距离报错失败，应该彻底拉近距离而不是每次只挪动最小的一步，然后在
重试前先用视觉确认距离已经足够近。

## 手持状态前置条件

- 同一时间只能持有**一个**物体。
- 已经持有物体时调用 `PickupObject(X)` 会报"already holding an
  object"类错误——先 `DropHandObject`、`PutObject`，或 `ThrowObject`，
  再重试拾取。
- `DropHandObject` / `PutObject(X)` / `ThrowObject` 都**要求**你当前
  手上确实拿着物体；空手调用会失败。

## "No valid positions to place object"

意味着目标容器从你当前的位置/朝向没有空闲/合法的放置位——通常是因为你
站得离目标表面太近或正好站在上面，又或者容器已经视觉上被占满。恢复
方法：后退一步（`MoveBack`）给放置求解器留出空间，或重新考虑这是不是
正确的容器实例（见下方"多实例歧义"）。

## 抽象动作不需要工具——不要去找工具

`SliceObject`、`CookObject`、`CleanObject`、`BreakObject` 等"抽象"交互
在这个环境里是简化过的：它们直接作用于目标物体，不需要你先找到/持有
刀具、炉灶或抹布。不要浪费步数去寻找辅助工具物体——一旦进入交互范围，
直接对目标物体执行相应动作即可。

## 切片/破碎后物体的标识会变化

- `SliceObject(X)` 生成 `XSliced`（例如 `SliceObject(Bread)` →
  `BreadSliced`，`SliceObject(Tomato)` → `TomatoSliced`）。
- `BreakObject(Egg)` 生成 `EggCracked`（不是 `EggSliced`——Egg 是这个
  命名规律的唯一例外）。
- 如果任务要求后续继续操作变形后的物体（拾取、烹饪、放置），必须改用
  **新的类型名**（`BreadSliced`、`EggCracked` 等），而不是原始类型名。

## 多实例歧义

当场景里有多个同类型物体（两个 `CounterTop`、两个 `Chair`、两个
`ArmChair`）时，环境会自动定位到**最近的可见**实例——你无法通过动作
字符串指定具体的某个实例 ID。如果一次交互"看起来成功"但状态变化的
物体看起来不对，很可能你离另一个实例更近；重新调整位置，让**目标**
实例在你视野里明确是最近的那个，再进行交互。

## 精确的 PascalCase 物体类型名

物体类型字符串必须与系统提示词目录中的写法完全一致（`HousePlant`，
而不是 `houseplant`/`Houseplant`/`House Plant`）。大小写或空格不一致
会产生"物体在场景中不存在"的报错，即使物体明明清晰可见——直接从目录
里复制类型名，而不是根据物体的外观自己拼一个英文名称。
