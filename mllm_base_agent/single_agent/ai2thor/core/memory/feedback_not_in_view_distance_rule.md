# "X is not in view" —— 用距离决定该"转身"还是"走近"

**Observed:** 这是 AI2-THOR 环境中最常见的交互失败信息之一（在 dual-agent
232 局的历史统计中出现 728 次，是单一最常见的错误消息；single-agent 的
"幻觉式完成"案例里也反复出现同类报错，见
`feedback_action_failure_blindness.md`）。它也是被最容易处理错的错误：
模型习惯性地"再靠近一点"，即便物体其实已经在交互范围内、只是没有出现
在画面正中央。

## 规则

错误信息里总会带上距离数字，例如：

```
Book is not in view, need to approach or adjust view (distance: 0.6m)
```

用这个距离数字决定恢复策略，而不是默认"移动"：

- **`distance < 1.0m`**（已经在交互范围内）：物体很近，只是没有出现在
  画面里。应该 **旋转**（`RotateLeft` / `RotateRight`）或者调整俯仰角
  （`LookUp` / `LookDown`），而不是继续移动——你已经在范围内了，移动
  只会把自己带偏。
- **`distance >= 1.0m`**：物体确实还远。应该**移动**靠近
  （`MoveAhead` 或更小粒度的变体），移动时让物体尽量保持在画面中间，
  每移动 1-2 步就重新观察一次距离，而不是一次性估算整段距离盲目移动。

## 实操恢复流程

1. 读取报错文本中的 `distance` 数值。
2. `distance < 1.0` → 只旋转/俯仰，不要移动。
3. `distance >= 1.0` → 朝物体上次可见的方向移动，每次 1-2 步，移动间
   隙重新观察（一次性移动过多容易再次导致物体超出画面范围）。
4. 如果旋转/俯仰两次后仍然完全看不到物体（连边缘都看不到），说明你对
   它所在方向的估计可能有误——做一次更完整的扫描（连续 2-3 次
   `RotateRight`）之后再假设它在别的房间或已经被移动。

## 反模式（不要这样做）

- 在收到"not in view"报错后重复完全相同的动作很少有帮助（如果一次
  没能让物体进入画面，第二次通常也不会，因为你相对物体的朝向没有实质
  变化）。改变恢复策略：换一个旋转方向、加上 `LookUp`/`LookDown`（物体
  可能在低矮/高处表面，如挂墙的 `LightSwitch`、床上掉落的 `Pillow`），
  而不是死板地重复同一个动作。
