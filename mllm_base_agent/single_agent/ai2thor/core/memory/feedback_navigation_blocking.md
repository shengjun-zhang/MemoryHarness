# 空间导航失败：被家具/墙体阻挡时如何脱困，而不是原地打转

**Observed:** 2026-07-28 single-agent AI2-THOR benchmark 中，33.1%
（103/311）的失败原因是 `Reached maximum step limit`。对触顶 step limit
的案例逐帧复盘后发现共性问题：agent 对家具碰撞体的认知很弱，被床、桌子、
冰箱、窗户、墙体挡住后，几乎唯一的应对策略是"旋转 90° 再试"，缺乏建图/
记忆能力，经常在原地画圈（连续 3-4 次 `RotateRight` 却没有实质位移），
把大半个 step 预算都消耗在无效的转向/位移上，而不是任务本身的交互动作。

在 AI2-THOR 中，一次被阻挡的移动**不会**模拟弹开或部分滑动——你会得到
**零位移**加一条报错信息。重复完全相同的被阻挡动作会一直失败，不会
"运气好"突然成功。

## 典型案例

- `ai2thor03059`（"Cook potato in pan"）：反复被冰箱/餐桌/墙体阻挡，
  多次转向摸索，直到耗尽 16 步预算仍未到达平底锅旁边。
- `ai2thor04051`（"Close laptop → move to coffee table"）：`CloseObject`
  连续 3 次因距离 1.3m 失败；后续被窗户/墙阻挡，反复原地转向找不到
  coffee table，16 步耗尽仍未完成。
- `ai2thor05071`（"Move ladle to dining table"）：从厨房到餐厅一路被
  冰箱、门框、柜台反复阻挡，几乎全部 step 都消耗在导航绕障上，直到
  结束都未能真正靠近餐桌。

## 脱困策略

1. **绝不重复刚刚失败的相同动作**——环境状态没有变化，完全相同的动作
   会得到完全相同的失败结果。
2. **优先尝试侧移**（`MoveLeft` / `MoveRight`）绕开正前方的障碍物，
   而不是单纯旋转后继续直走。侧移 + 前移的组合通常比连续旋转更快找到
   通路。
3. **如果大步幅移动被挡，尝试更小的步幅**（如把 `MoveAhead(Large)`
   换成 `MoveAhead(Small)`）——有时候只是超调冲进了一个障碍物，小步幅
   反而能通过。
4. **旋转角度要有变化，不要每次都转同一个方向 90°**——如果连续两次
   `RotateRight` 都没有找到出路，尝试反方向，或加大/减小旋转幅度，
   避免在两三个朝向之间来回摇摆。
5. **跨房间任务提前规划路线**：观察到门口/走廊后，优先朝其推进，而不是
   在当前房间反复扫描已经看过的角落。
6. **步数预算过半仍在原地打转时，立即改变整体策略**：换一条完全不同的
   路径，或退后几步重新评估房间布局全貌，而不是继续微调同一条被卡住
   的路径。

## 反模式（不要这样做）

- 不要把"被阻挡"当作信号去加大动作幅度（比如从 `MoveAhead(Small)`
  升级到 `MoveAhead(Large)`）——被挡住的路径无论步幅大小都还是被挡住，
  你需要的是**不同方向**，不是**更大的步子**。
- 不要连续 3 次以上朝同一方向做小幅度试探性移动而不评估是否真的有
  进展——如果 2 次尝试都没有带来画面变化，说明这个方向大概率走不通，
  应该切换方向或退后重新规划。
