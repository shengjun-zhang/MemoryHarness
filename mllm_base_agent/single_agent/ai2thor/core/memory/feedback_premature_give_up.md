# 过早放弃（FAIL）：探索半径太小就断言"物体不存在/任务无法完成"

**Observed:** 2026-07-28 single-agent AI2-THOR 全量 benchmark（311 个任务，
成功率 0%）中，9.0%（28/311）的失败原因是 `Model determined task cannot
be completed or refused to continue`（即模型主动输出 `FAIL`）。抽查 5 个
具体案例后发现，其中 **4/5** 属于"懒惰型放弃"：模型只在初始站位附近看了
1-3 个方向，或对同一个物体/同一个动作重复 2 次同样失败的尝试，就断言
"场景中没有这个物体"或"任务无法完成"，而 `golden_actions` 显示往往只
需要再走 1-2 步、换个角度就能看到目标物体。只有 1/5（`ai2thor05004`）
是模型做了充分尝试（多次移动/多角度靠近）后，确实被家具遮挡导致交互
距离卡死在 1.7m 附近，这种情况下放弃相对合理。

## 典型案例

- `ai2thor00000`（"Throw rotten lettuce away"）：仅原地旋转 3 次
  （0°→90°→0°→90°）看了 2 个方向，就断言场景中没有 lettuce，从未尝试
  移动到其他房间区域。
- `ai2thor05048`（"Toggle laptop on"）：仅执行 1 步 `LookDown` 看了一个
  视角，就断言"没有 laptop"直接 `FAIL`——而 golden_actions 显示需要先
  转向、移动才能看到目标。
- `ai2thor03029`（"Store potato in fridge"）：对着同一个柜子重复 2 次
  `OpenObject(Cabinet)` 均无效，未尝试移动、换角度、或打开其他柜子，
  就断言物体不存在直接 `FAIL`。
- `ai2thor04243`（"Close book & turn off lights"）：在起始桌子附近反复
  旋转/抬头低头找台灯，但 golden_actions 显示台灯在完全不同的方向且
  需要较大位移，模型未扩大搜索半径就放弃。

## 结论：这个 benchmark 里绝大多数任务在预算内是可解的

`FAIL` 应该保留给**真正**不可能/不安全的情形，而不是"看起来有点难就
提前退出"的手段。观测数据显示，大多数任务只需要在合理的探索/移动策略
下，在 `max_steps` 预算内即可完成——过早 `FAIL` 几乎总是模型自己的探索
不足，而不是任务真的无解。

## 输出 FAIL 之前的强制自检

在认定任务不可完成之前，必须先确认已经做到以下几点：

1. **至少完整巡视了一圈当前房间**：不能只看 1-2 个方向就下结论。从当前
   位置做 `RotateRight` × 3-4 次（覆盖 360°），必要时加上 `LookUp`/
   `LookDown`（很多物体在高处或低处，如 `LightSwitch`、掉落的小物件）。
2. **如果当前房间看不到目标物体，主动移动去探索其他区域**——不要假设
   目标物体只可能在你出生的第一视角附近。AI2-THOR 场景通常有多个房间/
   区域，golden_actions 里经常包含好几步移动。
3. **同一个交互失败不超过 2 次就切换策略类别**，而不是切换为直接放弃：
   - 打不开这个柜子/抽屉？试试旁边其他的同类容器。
   - 够不到这个物体？先靠近到 1.0m 以内再重试一次，而不是直接判定"不
     存在"。
   - 找不到物体？扩大搜索范围（换房间/换楼层区域），而不是原地重复。
4. 只有在完成上述系统性探索后仍然一无所获，且预算消耗已经比较多（比如
   超过 60%-70%）的情况下，才考虑 `FAIL` 是合理选择。

## 反模式（不要这样做）

- 不要把"第一眼没看到"等同于"不存在"。
- 不要用与上一次完全相同的动作重复失败后就直接放弃——先换个角度/位置
  再试一次，两次尝试都要有实质性差异。
- 不要在预算消耗不到 30% 的情况下就输出 `FAIL`——此时几乎一定还有充足
  的探索空间没有被使用。
